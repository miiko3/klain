# Klain Lab — 0.6 alpha

Окно Windows, в котором **Klain** запущен сразу во всех макетах iPhone/iPad.
Цель: не скачивать IPA с GitHub, а щупать функционал прямо на ПК и править код в реальном времени.

**Интерфейс перенесён 1-в-1 по настоящим SwiftUI-исходникам** из `Klain/` (`ContentView.swift`,
`HomeBanner.swift`, `ProvidersView.swift`, `ImageStudioView.swift`, `StatisticsView.swift`,
`GlassTheme.swift`, `ChatStore.swift` …): буквальные строки, заголовки секций, цвета, радиусы,
отступы, порядок элементов, названия кнопок. Используются реальные ассеты из
`Assets.xcassets` — иконка приложения и логотип рекламного блока.

## Запуск

Дважды кликни `ЗАПУСТИТЬ.bat` (или `npm start` в этой папке). Откроется отдельное окно Electron без адресной строки.

## Что именно работает (не демо)

- **Реальные запросы** к Anthropic / OpenAI / Google / OpenRouter / Vercel / своему OpenAI-совместимому API по твоему ключу.
- **Настоящий SSE-стриминг** ответов, остановка генерации, «мышление», usage/стоимость, генерация изображений (`/images/generations`).
- **Загрузка списка моделей** из API, проверка vision-моделей (бейдж «видит фото»), кастомные HTTP-заголовки.
- **Реальное сохранение** чатов, провайдеров, черновиков, статистики и картинок в `state.json` (папка `userData` Electron).
- Всё состояние **синхронизируется между всеми кадрами**: действие в одном макете сразу видно в остальных.
- Оболочка и приложение пишут состояние **независимо через частичный PATCH** — тема/инспектор/CSS не перетирают чаты и наоборот.

Локальный Node-прокси (`/api/proxy`) нужен, чтобы обойти CORS у провайдеров. Сервер слушает только `127.0.0.1`.
Разрешены `https://` и `http://localhost` (Ollama / LM Studio). Ключи не пишутся в логи.

## Макеты (реалистичная «железная» рамка)

18 классов экранов: SE/8/8 Plus, X/XR/11/12/13, 14/15/16 Pro и Pro Max, iPad mini/Air/Pro 11"/12.9".
У каждого реальные viewport-размеры в pt, титановая окантовка с градиентом и бликом, боковые кнопки
(без звука / громкость / питание), Dynamic Island с камерой и датчиком, классический notch,
home indicator и status bar с настоящими SVG-глифами (сигнал, Wi-Fi, батарея).

Слева: режим «все сразу» или «один крупный», чекбоксы устройств, масштаб, поворот, рамка, тема, status bar.
Клик по подписи устройства — увеличить его. Iframe рендерится в натуральном размере и масштабируется
через CSS `zoom` (а не `transform: scale`, который ломает композитинг iframe в Chromium).

## Визуальный редактор (справа)

- **Тема**: акценты, фон, панели, радиус, размер шрифта, плотность, сила стекла, светлая/тёмная, 4 пресета. Меняется мгновенно во всех кадрах и сохраняется на диск.
- **Инспектор**: включаешь → кликаешь любой элемент внутри макета → правишь текст/цвет/фон/размер/скругление/отступ/прозрачность. Правки запоминаются по CSS-селектору и применяются ко всем кадрам, переживают перезагрузку.
- **Свой CSS**: произвольный CSS injectится во все макеты.
- **Журнал**: кто и когда изменил файл.

## Живой цикл правок

`fs.watch` следит и за `KlainLab/app/*` (быстрая перезагрузка всех iframe, `scope: app`),
и за корневыми `index.html` / `shell.js` / `shell.css` (полная перезагрузка окна, `scope: shell`).
Правка файла → SSE-событие `reload` → макеты обновляются за ~0.3 с, тема и инспектор-правки
накладываются заново из состояния. Тебе не нужно ничего перезапускать.

Ты пишешь «кнопка серая / модель не подставляется», я правлю `KlainLab/app/app.js`, окно обновляется само.

## Поддержка Swift / языков Apple — что реально проверено

| Попытка | Результат |
|---|---|
| Запустить родной `Klain.app` / IPA на Windows | Нельзя: SwiftUI/UIKit/iOS SDK — проприетарные фреймворки Apple, есть только в Xcode на macOS |
| Установить Swift на Windows | **Сделано**: `Swift.Toolchain 6.4.2` через winget (`swift.exe` найден) |
| Скомпилировать SwiftUI-код | Нет: на Windows нет модулей `SwiftUI`/`UIKit`; тулчейну ещё нужен Windows SDK/stdlib + Visual Studio |
| Скомпилировать обычный Swift | Не удалось без Windows SDK (`unable to load standard library for target x86_64-unknown-windows-msvc`) |
| **Обход, который дал 1-в-1** | Прочитать все 14 `.swift`-файлов и перенести UI по буквальному спеку + реальные PNG-ассеты |

То есть «поддержка Swift» есть как установленный тулчейн и как **трансляция исходников в рабочий веб-порт**,
но не как исполнение нативного бинарника. Это единственный путь увидеть интерфейс на Windows без macOS.

## Структура

```
KlainLab/
  main.js          — Electron + loopback HTTP-сервер + прокси + SSE + PATCH + fs.watch
  preload.js       — безопасный мост к главному процессу
  index.html       — оболочка лаборатории
  shell.js         — каталог устройств, редактор, live-reload
  shell.css        — реалистичные рамки устройств
  app/
    device.html    — один макет (iframe)
    core.js        — состояние, API-клиент, SSE-парсер, normalize()
    app.js         — все экраны klain 1-в-1 + SF Symbols (SVG)
    app.css        — glassSurface / LiquidBackground / точные цвета
    assets/        — ad_logo.png, Icon.png из Assets.xcassets
  state.json       — в %APPDATA%/klain-lab (кнопка «💾 Данные»)
```

- **Новое лого** (`D:\фигма\1\Frame 10.png`): иконка приложения, favicon и эмблема на главном экране.
- **Оптимизация**: rAF-батчинг рендера markdown (1 кадр вместо каждого токена), дебаунс записи состояния

## Честные ограничения

- Это **не** родной бинарник `Klain.app`: логика перенесена в JS, UI приближен к Liquid Glass через `backdrop-filter`. SF Symbols заменены геометрически близкими inline SVG (проприетарные глифы Apple не распространяются).
- Нет Keychain (ключи лежат в локальном `state.json`), нет подписи IPA, нет фоновых background task iOS, нет камеры/PhotoKit (вместо «Камера» — сообщение «Камера недоступна»).
- Приложение в оригинале всегда в тёмной теме (`.preferredColorScheme(.dark)`); светлая тема в лабе — опция редактора.
- «Реальное время» = автоматическая перезагрузка при правке файлов, а не автономное непрерывное изменение кода: я меняю код, когда ты даёшь обратную связь.

## Отличия от iOS-версии (баги, исправленные в порте)

- `inputModalities` сохраняется при редактировании провайдера → vision-бейджи и блокировка фото работают.
- Провайдеры загружаются до создания первого чата → модель подставляется сразу.
- Можно выбрать протокол (`OpenAI` / `Anthropic` / `Google` / `OpenRouter`) прямо в редакторе.
- Разрешён локальный `http://localhost` для Ollama / LM Studio.
- Сохранение провайдера не сбрасывает модель текущего чата.
- `normalize()` защищает от битых/устаревших данных на диске (чат без `messages` больше не роняет экран).
